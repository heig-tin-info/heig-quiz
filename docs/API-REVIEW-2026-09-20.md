Scope: `apps/api/src/**`, `packages/contracts/src/*`, `toStudent` of every `qt-*`.
Paths are relative to `~/quiz`. Nothing was modified.

## Verified OK

- **One student exit.** `studentView`/`studentViewOf` is the only producer of a student payload (`live/studentView.ts:92-103`); `stripMetadata` runs on every type's output, `FORBIDDEN_STUDENT_KEYS` is applied recursively with a depth cap, and `studentView.leak.test.ts` sweeps the whole registry by forbidden key *and* by secret-value search. The four `toStudent` implementations are clean: mcq emits `{id,text}` only, short emits prompt/kind/placeholder, cloze collapses text/number/regex to `kind:"input"` (`domain/cloze.ts:224-241`), code publishes only `visible` cases plus `hiddenCount`/`hiddenPoints` and name+size for files. (The gap is `gradings.details`, which never goes through this exit — H1.)
- **IDOR.** `ownAttempt` filters on `attempts.userId` (a teacher genuinely cannot use the student routes); `staffAttempt` requires `(attemptId, evaluationId)` *and* `staffAccess`; `staffAnswer` / `staffGrading` reach the evaluation by join before the id match; every miss is `404 not_found`, never 403. `/join/:code` answers 404 for a wrong, disabled or archived code, and codes are 8×31 ≈ 40 bits.
- **SSE authorisation.** `resolveWatch` rejects a student watching someone else's attempt; the topic set is computed once at connect; `dashboard.*` is dropped twice over (`audience:"staff"` + `isStaffOnly`), and `grading.progress` rides the `audience` check. `runner.result` goes to `user:<id>` only.
- **Dev login.** `config.ts:136-138` throws under `NODE_ENV=production`; `plugin.ts:243` registers the routes only when the flag is on *and* the env is not production; `/app/api/config` mirrors exactly that condition. Same refusal covers `pglite://` and the two dev secrets.
- **Session cookies.** Opaque 256-bit token, only its SHA-256 stored, `httpOnly` + `sameSite=lax` + `secure` under production, sliding renewal mirrored onto both cookies, `DELETE` on logout, expired rows purged by the ticker.
- **Autosave.** One conditional upsert with `setWhere: revision < excluded.revision` — no read-modify-write; the loser gets `accepted:false` plus the stored payload. `GRACE_MS` lives once in `@quiz/domain` and is used by both `pastGrace` (the gate) and `expireDueAttempts` (the ticker). `now` is injected everywhere from `app.clock`; no `new Date()` drives a decision in `live`, `grading` or `results`.
- **Run button.** `assertWritable` first, per-question `runsPerMinute` counted from the journal, hidden cases filtered out by visible-case name, the source rebuilt server-side from template + regions (invariant 14, `qt-code/grade.ts:54-96`), `RunnerBusy`/`RunnerUnavailable` mapped to 429/503, retries only on 502/503/504, `AbortSignal.timeout` on both calls.
- **Grading.** `writeGrading` is the single writer: supersede + insert with `supersedes_id` in one transaction; a `proposed` write only supersedes a proposal, so an automatic pass can never unseat a validated grade; the two partial unique indexes (`answer_id`, `(attempt_id,item_id)` on `state='validated'`) make a concurrent double-write fail loudly; the pass skips validated cells (idempotent); regrade supersedes then re-queues rather than deleting. Release writes snapshot + `released_at` + state in one transaction; CSV/BOM (`EF BB BF`) and `;` are correct.
- **Assets (upload side).** Magic-number sniffing decides the type (SVG cannot match), `fastifyMultipart` limits `fileSize/files/fields` and `part.file.truncated` yields 413, sha256 dedupe with an `onConflictDoNothing` race path, `safeJoin` refuses any path escaping `ASSETS_DIR`, and the served response carries `nosniff`, `content-disposition: inline` and `default-src 'none'; sandbox`.
- **Error surface.** `app.setErrorHandler` replaces every ≥500 body with `{error:"internal_error"}`, so Drizzle's `Failed query: <SQL>` never reaches the browser; `invalid()` echoes only `{path, code, message}` from zod, never the submitted config or the expected literal.
- **Migrations.** `drizzle/0000..0003` are additive; no `DROP` anywhere.
- **Job parity.** `InProcessQueue` honours `singletonKey` for pending jobs, and `enqueueEvaluationGrading`/`enqueueRunnerGrading` fall back to inline execution when `app.boss` is absent rather than dropping the work.

## Follow-ups

Everything else in the table above was fixed on `main` (one commit per
finding, `2026-09-20`). These eight are deliberately left open; each line says
why, so that the next pass starts from a decision rather than from a
re-reading.

| id | why it waits |
|---|---|
| **M5** | Cross-course asset reads by any staff session. The link table the fix needs (`question_version_assets`) now exists and is filled at publication by the H3 fix, so the check is one join away — but tightening it is a behaviour change for teachers who share images across courses, and it needs the "reachable question" predicate the pool module does not expose yet. Do it with the pool-sharing work. |
| **M6** | `gradingQueue` materialises `attempts × items` with no cursor. It is a performance ceiling (200 × 40), not a correctness or safety problem, and paging it changes `GradingQuery`, the panel's fetching and its keyboard navigation at once. It belongs to the grading panel's own iteration, with a fixture big enough to measure. |
| **L1** | The CSRF token is never persisted, so the check is a pure double submit. `SameSite=lax` plus the cookie prefix is the real defence today and there is no sibling subdomain on the deployment; storing the token next to `sid_hash` touches the session table and the renewal path, which is the authentication work package's ground. |
| **L3** | Login-CSRF on `POST /app/auth/dev`. Development only by construction: `config.ts` refuses `AUTH_DEV_LOGIN` under `NODE_ENV=production` and the routes are not even registered there. Nothing to protect in production. |
| **L5** | Any session reads any avatar by uuid. Minor personal-data exposure inside one school, with unguessable ids; restricting it to users sharing a classroom needs a predicate the `avatar` module has no reason to own yet. Revisit if avatars ever leave the SPA. |
| **L6** | A strict CSP for the SPA belongs in the `Caddyfile`, which is deployed by hand on the VM (`deploy.md`) and not exercised by any test here. Writing it blind would either break Vite's dev origin or ship a policy nobody has loaded a page against. Do it on the VM, with the browser open. |
| **L8** | The two N+1 listings (`studentHome`, `studentResultCards`) cost a few dozen queries on pages a student opens a handful of times a day, against PGlite or a local Postgres. Worth one grouped query, not worth a rewrite before there is a class-sized dataset to measure it on. |
| **L9** | `ALPHABET[b % 31]` biases eight characters by ~3 %: 39.9 effective bits instead of 40 on a join code that is already rate-limited and revocable. Rejection sampling is three lines; it is listed here so it is a decision, not an oversight. |
