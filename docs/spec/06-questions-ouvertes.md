| 15 | Live poll: how to identify a participant without an account? | **Settled (ADR-014)**: a `quiz_guest` cookie (HttpOnly, `SameSite=Lax`, path `/app/api/p`, 12 h) of which the database only keeps `sha256(token:evaluation)`, and one `guest_participants` row per (poll, browser). `attempts.user_id` becomes nullable, `attempts.guest_id` appears, and a CHECK constraint imposes exactly one owner. | 16 | Live poll: does the end of a poll release results (`running → released` in the glossary)? | **Settled (ADR-014)**: no. "End poll" closes the poll (`closed`) and launches the deterministic grading, without release: releasing would write a frozen grade for the whole classroom, including the students who never saw the poll, and would make a 1.0 appear on their results page. The result of a poll is the projected distribution. |
| 17 | Code question: should the student's trial run in the browser (WASI) rather than in a container, and if so who grades? | **Settled (ADR-015)**: the browser runs, the server grades. `runtime` (`backend` by default, `runno` for C and Python) only chooses where the "Run" button executes; `grade()` always goes through the server's runner, because a result produced by a browser is not proof: WASI is not Linux (no `fork`, no signals, partial `<sys/…>`, the browser's clocks). The backend remains the fallback when the browser cannot (D14). The runtimes are hosted by the platform. |
| 18 | Poll: pseudonym for a participant without an account (F-AUTH-05)? | **Settled**: no, a guest is anonymous, full stop; the `pseudonym` field of `guest_participants` stays null and no UI asks for it. A freely chosen pseudonym is either a real name, and the poll is no longer anonymous, or noise on the projection; the distribution needs no identity. |
| 19 | Does a poll appear in the evaluation list of its classroom? | **Settled**: yes, with the "Poll" badge, since it is one (ADR-014); its row opens the projection and not the exam dashboard. Hiding it would make `mode: "poll"` a phantom evaluation, invisible where its classroom carries it. |
| 20 | Schematic question: how is a circuit graded, given that netlist comparison is out of scope (00 §0.6)? | **Settled (ADR-019)**: by SIMULATION of the output waveform, not by topology. The student's schematic and the teacher's reference are each rebuilt into a SPICE netlist server-side, run through ngspice (`apps/runner`, language `spice`) under every stimulus, and `v(out)` is compared by the rule of the stimulus's analysis: a transient passes when the normalised RMS distance is at or under `tolerance` times the reference's swing; an AC sweep (ADR-040) when its Bode plot stays inside an envelope around the reference's (`grading.bode`: gain within `magDb` above a floor `floorDb` under the reference's peak, phase within `phaseDeg`, one-sided below the floor). A circuit drawn differently that behaves the same is correct; an isomorphism check would need canonical forms for series/parallel merges and would still say no to it. The reference is simulated at grading time, never cached in the config. |
| 21 | Restoring a soft-deleted question: does it exist, or should the filter go? F-QST-11 specifies the soft delete (the question leaves the pool, its published versions stay readable) and requires no way back. Yet the pool screen offers a "Deleted" filter (`apps/web/src/pool/FilterBar.tsx`, `includeDeleted` in `pool/filters.ts`) that lists deleted questions with nothing a teacher can do to them: no restore route, and, since the audit of 2026-09-22 (B-11), no `restoreQuestion` service either — it was deleted as speculative, having never had a caller. | **Open.** Assumed for now: the filter stays, as the only way to see that a question was deleted rather than lost, and the pool keeps no restore. The two coherent endings are a `POST /questions/:id/restore` with the button the filter is missing, or dropping the filter and leaving a deleted question visible only through its frozen versions. Whichever is chosen, it settles both halves at once. |
| 22 | Code question: which wall-clock budget judges a VISIBLE case outside the grade? Since the audit of 2026-09-22 (R-06) the grade, the run route (`POST /attempts/:id/run`), the player and the editor's "try" share one rule (`caseVerdict` in `packages/qt-code`), comparison options included, except for time: the grade re-applies each case's own `timeMs` to the measured time, while the other three count only the runner's own `timedOut`, which is measured against the request's single, global budget. `CodeStudent` carries `limits.timeMs` but no per-case budget. The scenario is the one `packages/qt-code/src/grade.test.ts` pins ("times a case out on its own budget"): `limits.timeMs = 2000`, a case with `timeMs: 200` that runs in 900 ms reads "Passed" in the player and "Timed out" (0 points) in the grade — the residue of the ADR-015 §2 gap. | **Open.** Assumed for now: the player and the run route stay on the runner's `timedOut`, because a browser run's timing is not evidence (ADR-015) and the per-case budget is not published. The two coherent endings: carry each visible case's effective `timeMs` in `CodeStudent` and pass it to `caseVerdict` in the run route (and, if a browser timing is accepted as indicative, in the player), or drop per-case budgets altogether so the one global `limits.timeMs` is the only budget everywhere. Either one settles the three sites at once. |

The audit of 2026-09-22 (D-12) measured the cost and proposed keyset pagination; it is a contract change (`packages/contracts`) and roughly +40 lines in `GradingPanel`'s traversal, which is why it waited for the panel's decomposition (wave 5). | **Open, deferred** (campaign supervisor, 2026-09-23). Assumed for now: one unpaginated response, which holds for the classes of today (≤ 30 students). The coherent ending is keyset pagination on (item position, attempt) with the counts computed separately, so the panel's "validated / proposed" totals stay those of the whole selection; to be taken up before the first class of about 100 students is graded on the platform. |
| 24 | A teacher acting as a student (impersonation): what may they do — see only, answer, submit — and how is it shown in the audit? | 26 | Hiding a course a teacher no longer teaches (#155): a global archive of the course, a per-user hide, or both? And where does a hidden course still appear? | **Settled (ADR-032, 2026-09-27)**: per-user hide only, in `user_course_prefs(user_id, course_id, hidden_at)`; no global archive, no `course_staff` column (an admin reaches every course without a seat). | 27 | Do the grading criteria of a question (an essay's rubric, a short answer's `llm` rubric) reach a student when the evaluation shows the key (`showKey`, an exercise with immediate feedback included)? | **Settled (ADR-037, decided by the teacher on 2026-09-29)**: no, they are teacher-only. The key a student reads goes through the type's `studentSolution` hook in `studentSolutionView` (`apps/api/src/modules/live/studentView.ts`): an essay keeps its model answer (as the expected answer); the teacher's surfaces keep everything. A circuit's key is its reference alone, for everyone, and an `llm` matcher is refused at publication. Whether a student will read a per-criterion LLM breakdown in the grading details (04 §4.8, "Scoring, later") stays open. |
| 28 | The drill (ADR-041, #317): what the decisions of 2026-09-29 leave undecided. (a) Does deleting a classroom, an evaluation or a question delete the drill data it gave rise to? (d) Damping Easy on a question without variants, whose answer can be memorised? (e) Which evaluation's settings (negative marking, `categorizePolicy`) grade a review of a question met in several?
