| # | Question | Assumed in the spec |
|---|---|---|
| 1 | Project name, domain name, public or private repository | To be defined |
| 2 | edu-ID attributes available to tell a teacher from a student. Is `eduPersonAffiliation` provided by the HES-SO federation? Otherwise teachers are promoted by the admin. | Affiliation available, fallback on manual promotion |
| 3 | A late student in `duration` mode: full duration or common end? | Full duration, the teacher may close manually |
| 4 | Rounding of the grade: to the nearest tenth, or to the half point like some HES grade scales? | To the nearest tenth, configurable method |
| 5 | `immediate` feedback allowed in `exam` mode? | No, reserved for `exercise` and `poll` |
| 6 | Do students see the classroom ranking? | No, only their grade and the anonymous distribution |
| 7 | Runner languages in phase 1: C, C++, Python, JS, Rust. Rust compiles slowly, keep it? | Kept with a compilation time limit of 20 s |
| 8 | Are the hidden tests of a code question revealed in the feedback? | Name and verdict yes, content no, option per evaluation |
| 9 | The public pool: who may publish to it at first? | **Settled (ADR-013)**: a `public` pool is READABLE by every teacher; it is written by its owner and by the members the owner named (`contributor`, `owner`). The admin remains the de facto owner everywhere. |
| 10 | Format of the off-VM backups: Hetzner object storage or other? | Hetzner object storage through rclone |
| 11 | Drawing relies on embedded Excalidraw: accepted despite its own style? | Yes, reduced toolbar and aligned theme |
| 12 | An `exercise` evaluation with several attempts: best or last? | **Settled (ADR-025, #92)**: configurable per evaluation, `best` (ties to the latest) or `last`, with an optional maximum number of attempts. Each retake is a new blank attempt with a new seed; between attempts the student sees the score only. |
| 13 | Default LLM model for grading and for generation, and who pays: institutional key or the teacher's key? | Opus for grading, Sonnet for generation, the teacher's key |
| 14 | Design system: start from a precise visual reference? The screenshot provided shows the expected dashboard. | A design document to be written before the first screen |
| 15 | Live poll: how to identify a participant without an account? | **Settled (ADR-014)**: a `quiz_guest` cookie (HttpOnly, `SameSite=Lax`, path `/app/api/p`, 12 h) of which the database only keeps `sha256(token:evaluation)`, and one `guest_participants` row per (poll, browser). `attempts.user_id` becomes nullable, `attempts.guest_id` appears, and a CHECK constraint imposes exactly one owner. No fictitious account is created. |
| 16 | Live poll: does the end of a poll release results (`running → released` in the glossary)? | **Settled (ADR-014)**: no. "End poll" closes the poll (`closed`) and launches the deterministic grading, without release: releasing would write a frozen grade for the whole classroom, including the students who never saw the poll, and would make a 1.0 appear on their results page. The result of a poll is the projected distribution. |
| 17 | Code question: should the student's trial run in the browser (WASI) rather than in a container, and if so who grades? | **Settled (ADR-015)**: the browser runs, the server grades. `runtime` (`backend` by default, `runno` for C and Python) only chooses where the "Run" button executes; `grade()` always goes through the server's runner, because a result produced by a browser is not proof: WASI is not Linux (no `fork`, no signals, partial `<sys/…>`, the browser's clocks). The backend remains the fallback when the browser cannot (D14). The runtimes are hosted by the platform. |
| 18 | Poll: pseudonym for a participant without an account (F-AUTH-05)? | **Settled**: no, a guest is anonymous, full stop; the `pseudonym` field of `guest_participants` stays null and no UI asks for it. A freely chosen pseudonym is either a real name, and the poll is no longer anonymous, or noise on the projection; the distribution needs no identity. |
| 19 | Does a poll appear in the evaluation list of its classroom? | **Settled**: yes, with the "Poll" badge, since it is one (ADR-014); its row opens the projection and not the exam dashboard. Hiding it would make `mode: "poll"` a phantom evaluation, invisible where its classroom carries it. |
| 20 | Schematic question: how is a circuit graded, given that netlist comparison is out of scope (00 §0.6)? | **Settled (ADR-019)**: by SIMULATION of the output waveform, not by topology. The student's schematic and the teacher's reference are each rebuilt into a SPICE netlist server-side, run through ngspice (`apps/runner`, language `spice`) under every stimulus, and `v(out)` is compared: a stimulus passes when the normalised RMS distance is at or under `tolerance` times the reference's swing. A circuit drawn differently that behaves the same is correct; an isomorphism check would need canonical forms for series/parallel merges and would still say no to it. The reference is simulated at grading time, never cached in the config. |
| 21 | Restoring a soft-deleted question: does it exist, or should the filter go? F-QST-11 specifies the soft delete (the question leaves the pool, its published versions stay readable) and requires no way back. Yet the pool screen offers a "Deleted" filter (`apps/web/src/pool/FilterBar.tsx`, `includeDeleted` in `pool/filters.ts`) that lists deleted questions with nothing a teacher can do to them: no restore route, and, since the audit of 2026-09-22 (B-11), no `restoreQuestion` service either — it was deleted as speculative, having never had a caller. | **Open.** Assumed for now: the filter stays, as the only way to see that a question was deleted rather than lost, and the pool keeps no restore. The two coherent endings are a `POST /questions/:id/restore` with the button the filter is missing, or dropping the filter and leaving a deleted question visible only through its frozen versions. Whichever is chosen, it settles both halves at once. |
| 22 | Code question: which wall-clock budget judges a VISIBLE case outside the grade? Since the audit of 2026-09-22 (R-06) the grade, the run route (`POST /attempts/:id/run`), the player and the editor's "try" share one rule (`caseVerdict` in `packages/qt-code`), comparison options included, except for time: the grade re-applies each case's own `timeMs` to the measured time, while the other three count only the runner's own `timedOut`, which is measured against the request's single, global budget. `CodeStudent` carries `limits.timeMs` but no per-case budget. The scenario is the one `packages/qt-code/src/grade.test.ts` pins ("times a case out on its own budget"): `limits.timeMs = 2000`, a case with `timeMs: 200` that runs in 900 ms reads "Passed" in the player and "Timed out" (0 points) in the grade — the residue of the ADR-015 §2 gap. | **Open.** Assumed for now: the player and the run route stay on the runner's `timedOut`, because a browser run's timing is not evidence (ADR-015) and the per-case budget is not published. The two coherent endings: carry each visible case's effective `timeMs` in `CodeStudent` and pass it to `caseVerdict` in the run route (and, if a browser timing is accepted as indicative, in the player), or drop per-case budgets altogether so the one global `limits.timeMs` is the only budget everywhere. Either one settles the three sites at once. |
| 23 | Grading queue: paginate `GET /evaluations/:id/grading` before a class of 100 meets it? Today `gradingQueue` (`apps/api/src/modules/grading/service.ts`) answers every cell of the selection in one response — for 100 students × 20 items, 2 000 entries, each carrying its `studentView`, its `solutionView` and its grading history (superseded rows included), built before the `state` filter is applied. The audit of 2026-09-22 (D-12) measured the cost and proposed keyset pagination; it is a contract change (`packages/contracts`) and roughly +40 lines in `GradingPanel`'s traversal, which is why it waited for the panel's decomposition (wave 5). | **Open, deferred** (campaign supervisor, 2026-09-23). Assumed for now: one unpaginated response, which holds for the classes of today (≤ 30 students). The coherent ending is keyset pagination on (item position, attempt) with the counts computed separately, so the panel's "validated / proposed" totals stay those of the whole selection; to be taken up before the first class of about 100 students is graded on the platform. |
