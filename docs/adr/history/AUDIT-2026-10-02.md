## Overlap that should remain separate

These groups are related decisions, not duplicate records to merge:

- **Platform (001–012, 016, 028, 055):** framework, persistence, jobs,
  deadlines, runner isolation and operations have distinct trade-offs.
  Imported requirement IDs and obsolete deployment details need their status
  overlays; the deployment runbook owns actual operating commands.
- **Access and authoring (013, 017–024, 027, 032, 034, both 040, 051,
  053–054, 061):** sharing, personal preferences, preview, impersonation,
  API authorization and confined sessions have different trust boundaries.
  Repeated references to access invariants are useful local rationale.
- **Question types (015, 019, 021, 024, 036, 040 circuit, 046, 056):**
  trial execution, server grading, editing and parameterization are different
  responsibilities. AC stimuli extend transient circuit grading rather than
  replacing it.
- **Evaluation and feedback (014, 020, 025–026, 031, 033, 037, 044,
  050, 052):** templates, retained attempts, penalties, bonus points,
  publication and student-visible material each constrain a different step.
- **Statistics and drill (038–039, 041–043):** population selection,
  server-measured dwell, discrimination, distractors and spaced practice
  share data but settle different rules. Read 038's population before its
  extensions; do not infer that exercise attempts count in pool statistics.
- **LLM (045, 058–060, 063):** stub history, gateway, authoring, nightly
  review and grading remain separate. Start at 058 for infrastructure and
  063 for grading; 063 changes specific parts of 045/058 and permits a
  deliberate justification copy, not automatic disclosure of private criteria.
- **Merge and projects (007, 029, 035, 047–049, 057, 061–062, 064):**
  029 is wholly superseded by 035; 049 is only partially amended by 057.
  Project CI runners (007) and question execution (016) must not be conflated.
  Read 064 for project deadline application and 012 for freeze semantics.
- **Notifications (030):** common delivery guarantees recur beside each
  event's specific races and failure modes. Preserve those distinctions,
  especially the residual `pointsAcrossRegrade` limitation; avoid replacing
  them with a misleading promise of exactly-once delivery.
